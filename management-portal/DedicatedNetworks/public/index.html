CAMARA Dedicated Networks
Areas Profiles Networks Accesses

This portal walks through the four CAMARA Dedicated Networks APIs in the order they depend on each other: find a service area, reserve a network in it, then give devices access to that network. Each tab unlocks once the one before it has what it needs.

How to use this portal

The portal follows the Dedicated Networks workflow described on 5g-mag.com, Using CAMARA APIs: Dedicated Networks for Content Production. Each step is done by the ASP (Application Service Provider, the media application using this portal) or the CSP (Communication Service Provider, the network operator behind the API).

0. Pre-conditions

ASP CSP 0 On-boarding: sign up, access credentials, and the network profiles and service areas agreed with the operator.
In the portal: enter the CAMARA API base URLs and OAuth2 credentials in Config. The four dots in the top bar turn green when each API answers.

1. Before using the network

ASP 1.0a Discover the available network profiles (optional).
In the portal: the profiles are listed in 2. Network, and 1. Areas can filter areas by profile.

ASP 1.0b Discover the available network service areas (optional).
In the portal: 1. Areas: search by point, circle, polygon, name or profile, pick one and click “Use This Area”.

ASP 1.1 Request the reservation of a dedicated network.
In the portal: 2. Network: choose a network profile (or a QoS profile) and the service time.

CSP 1.2 The operator assesses the request and changes its status.
In the portal: 2. Network shows the status: REQUESTED, then RESERVED outside the service time and ACTIVATED during it.

ASP 1.3 Request device access to the dedicated network.
In the portal: 4. Devices (create devices by phone number and give one access to the network) or 3. Access. The access starts as REQUESTED; the operator grants or denies it.

2. During operation

ASP 2.1 Request device access, also while the network is running.
In the portal: 4. Devices and 3. Access work at any time.

CSP 2.2 The dedicated network is active and available.
In the portal: 2. Network shows ACTIVATED.

ASP 2.3 The device connects and uses the dedicated network.
In the portal: on the device itself; its access must be GRANTED and the network ACTIVATED.

ASP 2.4 Assign new devices and remove existing ones while the network is active.
In the portal: give access in 4. Devices; “Delete” an access in 3. Access or 4. Devices.

3. Dismantling

ASP 3.1a Delete the device accesses and the dedicated network.
In the portal: “Delete” in 3. Access or 4. Devices, and in 2. Network.

CSP 3.1b Or the operator tears the network down.
In the portal: 2. Network shows TERMINATED.

Shortcut: Quick Booking (a sub-case of steps 1.0b to 1.3)

Once you know the full path, Quick Booking runs one narrow case of it in a single form: the area is the one found at the location you click, the network uses the profile you pick and runs from now until the time you set, and one access is created for one phone number. Area search options, a later start time, QoS-only networks and more devices are only available in the full path.

Expected: the network and access it creates are the same objects the full path creates, and they appear in the Network, Access and Devices tabs afterwards.
